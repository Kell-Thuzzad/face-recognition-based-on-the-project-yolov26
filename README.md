# 人脸识别（YOLO26 + YuNet + ArcFace）

原项目基于 yolov8s 与 MTCNN，现已改为三级流水线：

1. **YOLO26**（`weights/yolo26*.pt`）定位人体，给出工位归属依据；
2. **YuNet**（`cv2.FaceDetectorYN`）在全分辨率原图上检人脸，输出框 + 5 关键点；
3. **ArcFace**（`weights/w600k_mbf.onnx`）按关键点对齐到 112×112 抽 512 维特征，与底库做余弦 1:N 比对。

`Haar.py` 是独立的 Haar 级联对比分支，不参与上述流程。

所有坐标均为输入图像的全分辨率像素值，全程不缩放原图。

## 模型文件

| 文件 | 大小 | 作用 | 来源 |
| --- | --- | --- | --- |
| `weights/yolo26s.pt` | 20 MB | 人体定位（默认） | Ultralytics 官方 YOLO26 |
| `weights/yolo26{m,n,l,x}.pt` | 5.5–118 MB | 人体定位（可切换） | 同上 |
| `weights/face_detection_yunet_2023mar.onnx` | 232 KB | 人脸检测 + 5 关键点 | opencv_zoo（LFS 端点下载） |
| `weights/w600k_mbf.onnx` | 13.6 MB | 人脸特征（默认） | insightface `buffalo_sc` 包 |

YOLO26 权重是 **COCO 80 类预训练，没有 face 类**，只用于定位人体，不要期待它直接输出人脸。
需要更高识别精度时换 `antelopev2` 包（zip 约 361 MB）里的 `w600k_r50.onnx`，用 `--rec-model` 指定即可。

## 安装

```bash
pip install -r requirements.txt
# GPU（如 RTX 5060）需换成 CUDA 版 torch，否则只会跑 CPU：
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu128
```

## 用法

```bash
# 1. 注册底库：gallery/ 下每个子目录名或图片文件名就是人员编号
python main.py -i gallery/张三人像.jpg -o out --gallery-dir gallery --build-gallery --no-display

# 2. 单图 / 目录
python main.py -i data/a2.png -o out --gallery-dir gallery

# 3. 视频文件或产线相机 RTSP 流
python main.py -i rtsp://user:pass@192.168.1.64:554/stream1 --gallery-dir gallery \
    --device cuda:0 --frame-stride 3 --json-out logs/line1.jsonl

# 4. 门禁近景（不需要人体定位，省掉 YOLO 一路开销）
python main.py -i 0 --no-person --gallery-dir gallery --device cuda:0
```

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `--conf` | 0.25 | 人体框置信度 |
| `--face-conf` | 0.6 | 人脸框置信度 |
| `--match-threshold` | 0.40 | 1:N 余弦相似度阈值，**必须用本厂样本重新标定** |
| `--frame-stride` | 1 | 视频流每 N 帧处理一次 |
| `--max-frames` | 0 | 最多处理帧数，0 为不限 |
| `--no-person` | 关 | 跳过 YOLO26 人体定位 |
| `--save-frames` | 关 | 视频流保存标注帧 |
| `--device` | 自动 | `cuda:0` / `cpu` |

## 输出契约

`<output>/results.jsonl` 每行一帧，供 MES / 考勤系统消费：

```json
{"ts": "2026-11-03T17:07:31.482", "source": "frame_000120", "image_size": [1920, 1080],
 "timings_ms": {"person_ms": 11.2, "face_detect_ms": 18.4, "recognize_ms": 9.7},
 "persons": [{"index": 0, "box": [747, 41, 1151, 712], "conf": 0.87}],
 "faces": [{"box": [113, 416, 155, 470], "score": 0.9159, "name": "A001",
            "similarity": 0.9475, "person_index": 1}]}
```

`gallery.npz` 是底库特征缓存（工号 + 归一化向量 + 生成它的特征模型名），命中缓存时不再重复抽特征。换 `--rec-model` 后加载旧缓存会直接报错，需加 `--build-gallery` 重建；删除该文件同样可重建。

## 实测性能（本机 CPU，torch 2.14.1+cpu，无 GPU）

| 环节 | 1280×720 单帧 |
| --- | --- |
| YuNet 全帧人脸检测 | 66–73 ms |
| ArcFace 对齐 + 特征 + 比对（`recognize_ms`） | 3 张脸 12.8 ms（首帧含会话初始化约 90 ms） |
| 单张脸特征推理（随机输入裸测） | 6.5 ms |
| YOLO26s 人体定位 | 1077 ms |
| 仅人脸链路（`--no-person`） | 79 ms/帧，约 12 帧/秒 |

**GPU 数据未实测**（本机 torch 为 CPU 版，`cuda.is_available()` 为 False）。按 YOLO26s 在 5060 上的常见量级估算人体定位约 10 ms，整链路可支撑 25 帧/秒单路；多路需按 `--frame-stride` 分摊。上线前请在目标硬件重跑本表。

比对余量（样本极少，仅作链路验证）：同一人 0.947 / 0.946，陌生人 0.06 / 0.03 / −0.01。

# 工厂落地方案

## 一、两套场景

### 场景 A：考勤 / 门禁（近景、1–2 人正面）

- 相机：门口 1080P 宽动态枪机或带人脸板的门禁机，安装高度 1.5–1.6 m，正对通行方向，补光避免逆光。
- 运行：`--no-person`（省掉人体定位）、`--frame-stride 2`、阈值取高（宁漏勿错放行）。
- 判定（在 MES/门禁控制器侧实现，本仓库只输出比对结果）：`similarity >= 阈值` 且人脸框短边 ≥ 60 px 才作为通行事件；其余进「待人工复核」。
- 防代打卡：本方案只做人脸比对，**不含活体检测**。若门禁有实物要求，需另配近红外/结构光活体或现场刷卡二次确认，不能只靠这一路 RGB 比对。
- 断网：识别在边缘盒子本地完成，事件先落本地 jsonl；补传需另配上传代理（本仓库未实现）。

### 场景 B：产线在岗与工位追溯（中远景、多人、侧脸遮挡多）

- 相机：工位上方 2–3 m 俯视或侧面枪机，单工位 1 路；一条线 6–12 路汇聚到边缘盒子。
- 运行：保留 YOLO26 人体定位，用 `person_index` 把人脸绑到人体框，再按相机标定表把人体框映射到工位号。
- 判定逻辑（在 MES 侧做，不在本仓库）：
  - **在岗**：某工位对应的人体框存在且该人体关联到已登记人脸；
  - **顶岗/未授权**：`name` 不在该工位班表内 → 告警；
  - **缺员/离岗**：连续 N 秒（建议 30 s）无对应人体框 → 告警；
  - **批次追溯**：把工号写入当班批次的操作记录，与质检结果绑定。
- 侧脸与遮挡：YuNet 对大角度侧脸召回下降明显，工位需保证至少一个相机能拍到正面；否则退化为「人体在岗 + 工牌」双因子。

## 二、部署拓扑

```
相机(RTSP) ──┐
相机(RTSP) ──┼── 交换机(厂区内网 VLAN) ── 边缘盒子/工控机 ──┬── 本地 jsonl（留存 30 天）
相机(RTSP) ──┘                                             └── HTTPS ── MES / 考勤系统
```

- 一台 5060 工控机经验值：单路 25 帧/秒全链路；4–8 路 1080P 按 `--frame-stride 3` 轮询可承载。
- 无 GPU 的盒子（Jetson/ARM）用 `yolo26n.pt` + `--no-person` + `--frame-stride 5`，或把人体定位换成 YOLO26 的 TensorRT 导出。
- 进程形态：每条线一个实例，`--json-out` 按天分文件；用 systemd/supervisor 拉起，异常退出自动重启。
- 相机时间同步：所有事件时间戳依赖 NTP，否则与 MES 的班次数据对不齐。

## 三、上线前必须完成的标定

1. **底库**：每人工号目录放 3–5 张不同光照/是否戴帽的正面照，`--build-gallery` 后向量取均值——单张底库照对口罩、帽子、老花镜的鲁棒性不够。样本里人脸框面积小于 40×40 px 的会被跳过，控制台打印跳过名单。
2. **阈值**：用本厂正负样本对（同人 500 对、不同人 5000 对）画 FAR/FRR 曲线，按业务选点。门禁建议 FAR ≤ 1/10000 对应的阈值（通常 0.5 以上）；产线在岗可放宽到 FRR ≤ 5%。默认 0.40 只是链路验证值，**不可直接用于放行**。
3. **工位映射**：标定每台相机视野内人体框坐标区间与工位号的对应表，随相机位置变动必须重标。
4. **验收指标**：底库 100 人规模下，正面照识别准确率 ≥ 99%；产线实际工况（侧脸、帽、口罩）单独统计，与厂方确认可接受水平后再签验收。

## 四、分阶段实施

| 阶段 | 周期 | 产出 | 通过条件 |
| --- | --- | --- | --- |
| POC | 1 周 | 单工位 1 路相机离线跑批 | 底库标定完成，阈值曲线出图 |
| 灰度 | 2–4 周 | 在线跑但不联动，只出报表 | 误报 ≤ 1 次/班次，漏检有记录 |
| 联动 | 1 周 | 接 MES 告警与批次记录 | 双人复核流程走通 |
| 推广 | — | 逐线复制 | 每条线单独标定工位映射 |

灰度期**只做提示不做控制**：不要让识别结果直接停机或开门，先由人复核，避免误识带来的产线损失。

## 五、合规要求（人脸属敏感个人信息）

- 依《个人信息保护法》，处理人脸信息需**单独告知并取得同意**，考勤场景需提供非生物识别的替代方式（工卡）且不得差别对待。
- 特征与底库**只存厂区本地**，不出内网；`gallery.npz` 存的是 512 维向量而非原图，但原图（`--save-frames`）属可识别个人信息，默认**不要开启**，确需留证时按岗位限定并设自动过期。
- 留存期限：事件记录与抓拍图建议 ≤ 90 天，离职人员底库照片在其离职后 7 日内删除并重建缓存。
- 权限：jsonl 与 npz 目录限制为服务账号可读；访问日志留存备查。
- 不要把 `gallery/`、`gallery.npz`、`--save-frames` 产物提交进代码仓库或同步到网盘。

## 六、运维与迭代

- **badcase 回流**：`similarity` 落在阈值 ±0.05 区间、或人工复核改判的帧，按工号归档，作为下一轮底库补录与阈值调整依据。
- **底库变更**：新增/离职人员只需改 `gallery/` 目录并重建缓存，无需重训模型。
- **模型升级**：`--rec-model` 换 `w600k_r50.onnx` 后，旧底库缓存会被程序拒绝加载（向量空间不互通）；重建底库后**必须重新标定阈值**，不同模型的相似度分布不在同一量级。
- **监控**：进程存活、每路相机断流（`无法打开视频源`）、单帧耗时 P95 超阈值、单位时间人脸数为 0 的路数。

## 七、已知限制

- YOLO26 权重为 COCO 预训练，只检 `person`；对工装、安全帽遮挡下的人体框可能偏大或漏检，工位映射需留容差。
- YuNet 在 320 输入尺寸下对小脸召回有限，本实现按原图分辨率检测（`setInputSize` 等于帧尺寸），高分辨率帧精度更好但耗时线性上升。
- 比对为单帧最近邻，没有跨帧跟踪：同一人连续多帧会产生多条事件，去重与停留时长统计需在 MES 侧按 `name + 时间窗` 合并。
- 口罩、安全帽、护目镜会显著抬升 FRR；本仓库不含活体检测与遮挡增强。
- 阈值 0.40 未经真实产线数据标定。

